# AGENTS.md — AI agent instructions for `halijahs-manasik`

This repository contains:

- An **Expo (expo-router) app** (primary) in `./app/`.
- A **Next.js CMS** (secondary) in `./cms/` that edits content and writes JSON to `./assets/data/`.

The mobile app is a “Spotify / e-book” style reading + audio playback experience:
- users browse **categories** → see a **dua list** (and subcategories) → open **dua detail** and optionally play audio.

---

## 1) Non‑negotiable rules

### UI primitives

- **Always use** `ThemedView` and `ThemedText`.
  - `ThemedView`: `./components/themed-view.tsx`
  - `ThemedText`: `./components/themed-text.tsx`
- **Do not use raw** `View` / `Text` from `react-native` directly.
  - Exceptions: platform wrappers such as `SafeAreaView`, `ScrollView`, `Animated.*`, `ImageBackground`, etc. are allowed; but all *visual containers and text* should be `ThemedView` / `ThemedText`.

### Don’t break contracts

- The app depends on these canonical data sources:
  - `./assets/data/categories.json`
  - `./assets/data/duas.json`
- Types are defined in `./config/types.ts`. Keep JSON compatible with these types.

### Keep changes minimal

- Avoid broad refactors and “style rewrites”.
- Match existing patterns (navigation, hooks, font loading, naming).

## 2) Quick start (local dev)

### Expo app

From repo root:

```bash
npm install
npm run start
```

> Note: `npm install`/`npm run start`/`npm run lint` already run `npm run brand:select` via `package.json` `pre*` scripts.

#### White-label build (select brand assets)

Brand assets are selected at build time by setting `COMPANY_ID`.

Valid `companyId`s (currently):
- `manasiktech` (default)
- `halijah`

```bash
export COMPANY_ID=manasiktech
npm run start
```

If you change `COMPANY_ID`, re-run `npm run brand:select` (or restart any script that triggers it) to regenerate the `assets/images/**/current` folders.

The selection logic lives in `./scripts/select-brand.mjs` and generates:
- `./assets/images/current/*`
- `./assets/images/button-bg/current/*`

### Web preview (Expo export served on port 8080)

```bash
npm run web:build
npm run web:serve
```

### CMS dev

> First time only: install CMS dependencies (`cms/` has its own `package.json`): `cd cms && npm install`

```bash
npm run cms:dev
```

### CMS + App preview together (recommended)

This runs:
- CMS on `http://localhost:3000`
- Web preview served from `dist/` on `http://localhost:8080`

> Note: `npm run cms` serves `dist/` but does not build it; run `npm run web:build` first (and rerun it when the web preview needs refreshing).

```bash
npm run cms
```

> The CMS iframe preview URL is controlled by `cms/.env.local` via `NEXT_PUBLIC_PREVIEW_APP_URL`.

## 4) Expo app architecture (high-signal)

### Navigation model (expo-router)

- The app uses file-based routing.
- Primary UX is under `./app/(tabs)/home/*`.

Typical flow:

1. `Home` (`home/index.tsx`) renders buttons for category keys.
2. On press it calls `loadDuas(categoryKey)` from `useDuaLoader`.
3. If 1 dua → navigate to `duaDetail`.
4. Else → navigate to `duaList`.

Key loader hook:
- `./hooks/useDuaLoader.ts`
  - filters `duas.json` by `categoryKey`
  - includes subcategory logic via `categories.json`
  - applies **Hajj/Umrah mode** filtering via `HajiUmrahFilterContext`

### Hajj/Umrah filtering (important)

- Mode comes from `./contexts/HajiUmrahFilterContext.tsx` (used by `useDuaLoader` and sorting).
- `duas[].categoryKey` must include either `"haji"` and/or `"umrah"`.
  - If a dua is missing the mode tag, it may silently disappear.

### Sorting (order fields)

- Sorting is applied in `./hooks/useSortedDuasAndCategories.ts`.
- `CategoryType.order` (number) is used for subcategories.
- `DuaType.order` is a map: `{ [categoryKey: string]: number }` for category-specific ordering.

### Audio playback (assets must be mapped)

- UI control: `./components/controls/dua-player.tsx`.
- Audio state: `./contexts/AudioContext.tsx`.
- **All playable audio filenames must exist in** `AudioMap`:
  - `./components/controls/audio-files.tsx`

If you add a new mp3:
1. Put it in `./assets/audio/`.
2. Add an entry to `AudioMap` with the exact filename.
3. Reference that filename in `duas.json` under `audio`.

### Favourites

- Stored in `AsyncStorage` under key: `favourited_duas`.
- Hook: `./hooks/useFavourite.ts`.

### UI scaffolding patterns

- Prefer `ParallaxScrollView` (`./components/parallax-scroll-view.tsx`) for screens with hero headers.
- Use `expo-image` for images (already used across screens).
- Maintain accessibility attributes on pressables where present.

## 5) Content model (JSON contracts)

### Categories (`./assets/data/categories.json`)

Shape:

- `{ categories: CategoryType[] }`
- `CategoryType` in `./config/types.ts`:
  - `key: string` (lowercase, used for lookups)
  - `nameEn`, `nameMy`
  - `subcategories?: { key, nameEn, nameMy, order? }[]`
  - `global?: boolean`

Rules:

- **Keys are identifiers**. Keep them stable.
- Many keys are lowercased and may include spaces/apostrophes (e.g. `"masjidil haram"`, `"sa'i"`).
- Ensure keys referenced in `HOME_SCREEN_BUTTONS` match category keys exactly.

### Duas (`./assets/data/duas.json`)

Array of `DuaType` (`./config/types.ts`):

- `id: number` (unique)
- `titleEn`, `titleMy`
- `doa: { id, arabic, translationEn, translationMy }[]`
- `categoryKey: string[]`
- `audio?: string | null`
- `order?: Record<string, number>`

Rules / gotchas:

- `categoryKey` must include mode tags (`"haji"` and/or `"umrah"`).
- Category matching frequently uses `category.toLowerCase()` in loaders.
  - Prefer storing category keys in lowercase in JSON.
- If `audio` is set, it must be present in `AudioMap`.

## 7) CMS (secondary) — how it relates to the app

### CMS edits JSON directly

- CMS API routes use Node `fs` to read/write:
  - `./assets/data/duas.json`
  - `./assets/data/categories.json`
- IO helpers: `./cms/app/lib/data.ts`

### Live preview pipeline (CMS → App)

- CMS renders an iframe to the Expo web preview:
  - sender: `./cms/app/component/PreviewFrame.tsx`
  - env: `NEXT_PUBLIC_PREVIEW_APP_URL` (see `cms/.env.local`)
- CMS sends `postMessage` with type `MANASIK_DATA_UPDATE`.
- App listens and swaps data sources:
  - receiver/provider: `./contexts/CMSDataContext.tsx`
  - consumer: `./hooks/useDuaLoader.ts` (uses CMS data when available)
- Optional focus-on-dua behavior:
  - CMS can send `selectedDuaId`, and `home/index.tsx` will navigate to detail.

### CMS authentication

- Supabase auth is enforced via middleware.
- Env values live in `cms/.env.local` / `cms/.env.production`.
- Do not log or expose secrets.

## 9) Performance guidance (after correctness)

- Avoid re-render churn in lists:
  - prefer memoized list items (see `home/duaList.tsx` patterns)
- Avoid heavy computations during render:
  - use `useMemo`/`useCallback` when working with `duas.json` (large file)
- Keep images optimized; use `expo-image` caching.

## 10) If you’re unsure what to change

For any request, start by answering:

1. Is this UI, content, release, or performance?
2. Which route/screen is impacted (`app/(tabs)/**`)?
3. Which data keys are involved (category key, dua id, audio filename)?
4. Which asset needs to be added or re-mapped?

Then make the smallest coherent change and validate via:

```bash
npm run lint
```
